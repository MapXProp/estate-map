# Article and public-page SEO audit — 25 September 2026

## Scope and findings

- Read-only production crawl of all 170 URLs in `/sitemap.xml`, including `/blog`, all ten articles, property/category pages, organizations, transit directory, About and Contact.
- Every sitemap URL returned HTTP 200 directly, one H1, one nonempty title and description, one self-referencing canonical and index/follow. Titles were unique. No accidental noindex or malformed JSON-LD was found.
- The existing sitemap already included every article and its cover image. Robots.txt already advertises the sitemap. `/` redirects to `/homes`; `/rent` canonicalizes to `/rooms`. These aliases remain excluded.
- Fourteen distinct social-preview images for the articles and selected public pages returned HTTP 200 with image content types. All ten articles have BlogPosting and breadcrumb data, real content and source references.
- Account/authentication pages, filtered search and nonexistent pages were checked separately. They are not sitemap entries. No Search Console submission, Google index-status check or Rich Results Test was performed.

## Changes

- Generate the Blog index's sitemap modification date from the newest article update instead of the shared initial publication date. New article entries and images continue to be generated from the article catalog automatically; empty catalogs do not invent a date.
- Use each article's own publication date in social metadata and BlogPosting. Retain the actual 24 September publication dates of the existing ten articles. Publication and modification dates can now differ without failing the content regression check.
- Match the structured author name to the visible editorial byline; link that byline to About and connect the publisher to the site's existing Organization entity.
- Add AboutPage and ContactPage data connected to the existing WebSite/Organization entities. Page layout and copy remain unchanged. These schemas describe the pages; they do not promise a special Google search appearance.
- Fix a discovered HTTP 500 on `/real-estate-categories/all?q=condo` and `?q=house`: the public API returns `offer_types: null` for an unfiltered buy/rent intent, while the price filter expected an array. Treat null as unfiltered and accurately type the nullable field. Preserve real prices and filtered-search noindex/follow.
- Retain the site's Thai language and initial-head Google `notranslate` opt-out.

## Validation and maintenance

33 regression tests covering SEO, blog content/sitemap dates and listing prices passed. The null offer filter was reproduced with a failing regression before the fix. Scoped ESLint passed. Production crawl scripts and before/after evidence are kept in `work/seo-current-2026-09-25/` in the parent workspace, along with build/deployment results.

When publishing an article, add a unique handle, accurate title/excerpt, relevant local image and alt text, publication `datetime`/display `date`, actual `updatedAt`, real author and source links in `src/data/blogPosts.ts`. Sitemap coverage is automatic. Update `updatedAt` only for a meaningful editorial change; do not replace dates with today's build time. Public inventory still comes from the API with the existing five-minute revalidation and incomplete-response safeguards. Split the XML sitemap before Google's 50,000-URL/50-MB uncompressed limit.
