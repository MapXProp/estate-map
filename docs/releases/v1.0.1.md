# MapXProp web 1.0.1

Place autocomplete correction after the 1.0.0 baseline. The `v1.0.0` tag remains unchanged; no API/database migration is required.

- Header, home search, mobile search sheet, map search, catalogue search and the legacy location field share Longdo place completions and registered project names. Listing titles, database address groups and extra local station rows are not inserted into autocomplete. Full listing keyword search and stored administrative addresses remain available.
- Completion starts at three characters with a 300 ms debounce. Longdo Suggest handles incomplete words; typed English requests English place details when resolved. Plain words are rendered instead of provider HTML. Quotas, short-lived caches and request cancellation remain in place.
- The listing pin picker uses only Longdo. Selecting a completion resolves actual coordinates; ambiguous names present their addresses for selection. Selecting a new location clears previous confirmation, and the user must still confirm the exact map point. Enter/search can also resolve a typed full address directly.
- Existing map navigation preserves transaction, category and price filters. Registered projects retain their own identity and coordinates.

Validation: frontend unit/integration suite, ESLint, production build, real Longdo English/Thai prefix and coordinate probes, and read-only browser checks at 390/820/1440 px. Browser fixtures exercise delayed resolution, homonyms, provider failure, stale requests, mobile sheet navigation and map filter preservation. Evidence is in workspace `work/place-autocomplete-2026-09-26/`. No test listings were posted to production; physical iPhone/Android keyboard behavior was not tested.

Longdo controls the available names and provider ranking. English/Thai prefixes work with its index; this does not guarantee every spelling variant or Google's ranking.
