# MapXProp 1.0.0

Stable product baseline, September 2026. The website remains online; feature development is frozen at this release. Subsequent corrections should use a new patch version instead of moving the `v1.0.0` tag.

The package version now represents MapXProp's product release, replacing the inherited template version 2.2.0.

## Listing publication

- A title, description, confirmed map coordinates, province, applicable prices (or price on request), contact name/phone/role, and at least one property photo are required. Other existing category and field validations remain in place.
- Missing photos are highlighted at the upload field before any upload starts. Video, panoramas and event floor plans do not replace the required property photo.
- Existing images remain usable when editing. Removing the last image is rejected when replacing listing media; an API edit that retains existing media leaves it intact.
- Retail rent must be positive on both client and server. The API also enforces title length, required contact information and finite prices/area values.
- Slow cloud autosaves cannot overwrite newer local edits, restore a cleared draft or assign a response to another account. Superseded queued snapshots are skipped.
- Draft requests have an 8-second deadline, publication 30 seconds, and media uploads 120 seconds per file. Failed requests preserve the draft and the submission key for retry. Saving reusable contact defaults does not block publication.
- Existing retry behavior retains successfully uploaded files and prevents duplicate listings using a persisted submission key.

## Release checks

- Frontend automated tests: 417 passed.
- Backend unit/integration suite passed against isolated PostgreSQL, including all 23 selectable category routes, media ownership, editing, moderation, and 8 concurrent submissions with the same key.
- Browser publication matrix: 35/35 passed; required-field correction flow: 7/7 checks passed; blank-form and upload/save retry scenarios: 2/2 groups passed. Browser checks use actual uploads and database persistence in an isolated environment, covering desktop, tablet and mobile viewport sizes, required-field corrections, failed uploads/saves, and refresh after success.
- Build, deployment revision and final browser evidence are recorded under workspace `work/listing-v1-audit-2026-09-26/`.

No synthetic listings are published on production. Physical iPhone/Safari and Android hardware, production write load, outbound email delivery and all possible network failures are outside this verification. The release is a tested baseline, not a guarantee of zero defects.
